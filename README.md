# Where the Seconds Go

A speed limit in seconds, and an accounting of the gap to it, for Mixture-of-Experts decode on one consumer GPU with
the experts in host memory.

Paper: `paper/paper.pdf` (source `paper/paper.tex`; every number in it is a macro generated by the scripts below from
`prereg/*.json`). GPU job scripts, raw measurements and routing traces: branch `gpu` (`jobs/`, `results/`); each job's
predictions are in its script's header, committed and pushed before the machine started, and git history orders every
prediction before the measurement it concerns. Outcome notes and the scorecard: `prereg/`.

## What this is

Running a large MoE model at batch 1 on a desktop GPU means keeping most experts in host DRAM, and each decoded token
then reads its routed experts from GPU memory, from host memory by the CPU that runs the expert, or from host memory
across PCIe into a GPU slot. The paper asks how fast such a machine could decode, how far real systems are from that,
and what separates them, on rented RTX 5090 / 4090 / 3090 hosts with gpt-oss-120b and Qwen3-30B-A3B.

1. **A host-memory law** (`scripts/wsg_tables.py`, `jobs/ec2/fetch_table.py` on `gpu`): time per token = a GPU term
   plus host bytes over the probed rate of the read paths in use, predicted blind on seven RTX 5090 hosts and re-scored
   with frozen constants on three later ones (`scripts/law_frozen_later.py`). It is a calibrated model of execution that
   reads host memory in sequence with GPU work; its job in the system is to pick, per machine, how many of a layer's
   missed experts to copy over PCIe and how many to run on the CPU.
2. **A speed limit in seconds** (`scripts/speed_limit.py`, `mosl/cachesim.py`): a ceiling for exact-routing systems with
   C expert slots per layer, from Belady's MIN with bypass on the model's own routing trace, two host read paths and
   the machine's measured ceilings, tightened four ways (`prereg/speed_limit_v2.json`); the pooled-cache variant for
   systems without a per-layer budget (`prereg/pooled_fractions.json`); an audit of 52 published measurements against
   a datasheet version of it (`scripts/audit.py`, `scripts/audit_table.py`, `prereg/audit/`).
3. **An accounting and its measurement** (`scripts/shapley_gap.py`; `scripts/foresight_stats.py`,
   `scripts/foresight_paper.py`, `scripts/foresight_latency_sim.py`, `scripts/foresight_single_read_sim.py`): a Shapley
   attribution of the gap to the limit over five modelled fixes, then oracle policies run inside the engine with the
   routing of the coming steps (jobs 093, 094 and 095 on `gpu`): a hit-optimal prefetcher, MIN with bypass with
   background admissions, and single-read oracles whose admitted experts are read once (fetched into their slot, or
   prefetched with a lead). `prereg/foresight_09*.json` and `prereg/foresight_outcome_09*.md`.
4. **What nine models' routing traces say** (`scripts/foresight_exact.py`, `scripts/policy_gap.py`,
   `scripts/batchk_trace.py`, `mosl/`): which online policy earns its reads, how fast the hot set drifts, how many
   tokens of foresight are worth half the optimum (W50 ≈ 0.59 (C/k)^1.33), and what batched speculative verification
   cannot buy.
5. **The instrument** (`runtime/llama.cpp-expert-cache-4da6337.patch`; the oracle version
   `jobs/ec2/llama.cpp-expert-cache-4da6337-oracle.patch` on `gpu`): a llama.cpp expert cache with per-layer slots,
   decayed-frequency admission, GPU-signalled CPU helpers through a mailbox, FETCH of missed experts into slots by a
   per-machine table from the law, and the `llama-ec-bench` teacher-forced benchmark, measured against FreeToken and
   llama.cpp on four cards (`scripts/stockclock_stats.py`, `scripts/grid_stats.py`, `scripts/headline_stats.py`).

## Reproduce the paper's numbers

```bash
git clone -b gpu <this repository> ../gpu-branch          # the results and job scripts
export MOSL_RESULTS=$PWD/../gpu-branch/results MOSL_GPU_BRANCH=$PWD/../gpu-branch
pip install numpy numba scipy matplotlib
python scripts/scorecard.py && python scripts/wsg_tables.py && python scripts/wsg_numbers2.py \
  && python scripts/grid_table.py && python scripts/foresight_paper.py && python scripts/audit_table.py \
  && cd paper && latexmk -pdf paper.tex
```

The statistics behind the macros are recomputed from the raw results with `scripts/stockclock_stats.py`,
`scripts/grid_stats.py`, `scripts/foresight_stats.py --job <job>`, `scripts/foresight_latency_sim.py`,
`scripts/foresight_single_read_sim.py`, `scripts/law_frozen_later.py`, `scripts/speed_limit.py` and
`scripts/shapley_gap.py`; each writes the `prereg/*.json` file the macros read.

GPU jobs run through `gpu/vast.py` (`offers`, `launch <offer> <job>`, `logs`, `fetch`, `destroy`): a job is a script
under `jobs/` on branch `gpu` whose header carries its predictions; the runner boots the rental, runs it and returns
`results/<job>/` through the log channel.
