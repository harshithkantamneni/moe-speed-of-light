# Seconds, Not Blocks

A validated speed-of-light for offloaded Mixture-of-Experts decode, and what it says about published speed-ups.

Paper: `paper/paper.pdf` (source `paper/paper.tex`; every number in it is generated by `scripts/paper_numbers4.py`).
Pre-registrations and outcomes: `prereg/PROTOCOL.md`. GPU job scripts, raw measurements and trace packs: branch `gpu`
(`jobs/`, `results/`); git history orders every prediction before the measurement it predicts.

## What this is

Running a large MoE model on one consumer GPU means keeping most experts in host memory. Dozens of systems report
decode speed-ups over llama.cpp for this setting. This repository provides the yardstick those claims lack, and uses it.

1. **A speed-of-light in seconds.** A lower bound on batch-1 decode time for *any* exact-routing policy under a
   per-layer or shared GPU expert budget (static or dynamic, demand or prefetching, misses fetched or executed on the
   CPU), computed from exact routing traces (`mosl/perfmodel.py: speed_of_light_time`; tested against every simulated
   policy, including an oracle prefetcher, in `tests/test_bound.py`).
2. **A validated decode model.** Bytes over bandwidth with measured efficiencies: 16 % median error on 52 third-party
   measurements from 9 sources (cross-validated, one of 12 groups held out at a time); tested on pre-registered
   first-party runs (A10) and anchor runs (GH200), where its transferred constants are conservative with experts
   offloaded; calibrated with two runs, it predicted 29 held-out configurations on the GH200 with 6.7 % median
   error (registered as H5).
3. **An audit.** 147 published measurements from 41 systems, re-checked field by field against every source. 22 rows
   are adjudicable: 16 of 20 llama.cpp baselines fall below the band of the predicted equal-memory `--n-cpu-moe`
   baseline, 8 of 22 claimed gains survive against it, and the median system reaches 24 % of the physical
   speed-of-light. None of the 15 papers with a llama.cpp baseline configured its partial expert offload.
4. **Trace provenance.** Teacher-forcing dataset text (the norm in trace studies) overstates cache hit rates against
   the models' own generations on all nine models traced (3.3–5.4 points on the four pre-registered models at 12.5 % of
   experts, up to 8.8 on the audit's models); for gpt-oss-120b, dataset text without its own reasoning is
   off-distribution.

## Quick use: where does a result stand?

```bash
python -m mosl.calc --repo Qwen/Qwen3-30B-A3B-Instruct-2507 --b-exp 4.85 --b-dense 4.85 \
    --bw-gpu 1008 --bw-cpu 89.6 --bw-pcie 31.5 --budget-gb 8 [--trace <pack>.npz]
```

prints the physical speed-of-light (per-layer and pooled budget) and the predicted llama.cpp `--n-cpu-moe` baseline
at the same GPU memory, with its error band. Pass a trace pack of the evaluated text for exact misses; without one,
independent routing is assumed (more misses, so a lower, still valid bound).

## Layout

| Path | What it does |
|---|---|
| `mosl/collect.py` | Layer-streamed, teacher-forced trace collector: exact routing of any corpus, one decoder layer in memory at a time (CPU, GPU, or tensors streamed over HTTP). Qwen3-MoE, Qwen2-MoE, OLMoE, DeepSeek-V2, Mixtral, PhiMoE, gpt-oss (MXFP4 and bf16). |
| `mosl/cachesim.py`, `mosl/ecsim_fast.py` | Trace-driven expert-cache simulation (LRU, LFU, static, DFA, Belady MIN, MIN-bypass; per layer and global). |
| `mosl/perfmodel.py` | Decode model (Eq. 1) and the speed-of-light bound (Proposition 1). |
| `mosl/archs.py`, `mosl/gguf_bytes.py` | Exact bytes per parameter class from a meta-device instantiation or a GGUF header. |
| `mosl/calc.py` | The calculator above. |
| `data/audit/` | The audit set: raw extractions with verbatim evidence (`rows_group*.jsonl`), normalized rows, the independent re-check (`verify_batch*.jsonl`, `verification.md`), exclusions, schema. |
| `data/published_measurements.json` | Third-party decode measurements of the validation set, each with source and quote. |
| `data/traces_manifest.json` | Every released trace pack (branch `gpu`), with shape and SHA-256. |
| `scripts/audit.py` | The audit (predicted baseline, band, speed-of-light, labels). Outputs `prereg/audit/`. |
| `scripts/provenance.py`, `scripts/global_gain.py`, `scripts/harmony_class.py` | Trace provenance, pooled-budget effect, gpt-oss-120b classification. |
| `scripts/anchor_predict.py`, `scripts/anchor_score.py` | Anchor predictions (committed before measuring) and their scoring. |
| `scripts/paper_numbers4.py`, `scripts/fig_audit.py` | Every number, table and figure of the paper. |
| `runtime/llama.cpp-expert-cache.patch` | Our own expert cache with GPU-signalled CPU helpers, the system under test in the paper's case study (against llama.cpp 2145525a). |
| `runtime/ggml-sched-overlap.patch` | Stand-alone ggml scheduler change: run a CPU split concurrently with the preceding GPU split when it does not depend on it. |
| `tests/` | Collector exactness (selections and NLL against `transformers`, prefill and KV-cache decode, 8 checkpoints), MIN/MIN-bypass optimality against exhaustive search, bound validity. |

## Trace packs

`results/<job>/<model>_<arm>.npz` on branch `gpu`: `routes[layer, token, k]` (sorted expert ids), `seq_lens`,
`prompt_lens`, `corpus_idx`, `nll`, `meta`. Arms: **D** dataset answer teacher-forced; **G** the model's own greedy
answer; **S** its own sampled answer (generation-config defaults, seed = prompt index). Load with
`mosl.traces.load_pack`. Decode steps are the answer tokens (`prompt_lens[i]..seq_lens[i]`).

## Reproduce

```bash
pip install torch transformers==5.17.0 safetensors huggingface_hub numba scipy numpy matplotlib
python tests/test_cachesim.py && python tests/test_collect_equivalence.py && python -m pytest tests/test_bound.py -s
python scripts/validate.py                                  # model fit and grouped (leave-one-group-out) CV
python scripts/audit.py --results <gpu-branch>/results --out prereg/audit
python scripts/provenance.py --results <gpu-branch>/results --out prereg/provenance
python scripts/paper_numbers4.py --results <gpu-branch>/results --out paper && cd paper && latexmk -pdf paper.tex
```

GPU jobs run through a git-driven runner (`gpu/runner.sh`, `gpu/lambda.py`): a job is a script under `jobs/` on
branch `gpu`; the runner executes it and commits `results/<job>/`.
