### Step 1 — Engine: two flags and randomised order (2–3 days, $0)

All in `/home/claude/scratch/lc-ec`; test every mode on the CPU build (`build/bin/llama-ec-bench` with
`LLAMA_EC_*`) against the simulator before any rental, as job 095 was.

**1a. Online fetch-on-admit** (`LLAMA_EC_FETCH_ON_ADMIT=1`): the deployed decayed-frequency policy, but an expert it
would admit is fetched into its slot in the step that misses it (one read) instead of being served on the CPU and
copied in the background (two reads). This is the control both reviews name (the online policy's own 3–7
double-read admissions per token are part of the "bytes foresight saves" step) and a practical result.
Implementation sketch (file:line in `src/llama-expert-cache.cpp` and `ggml/src/ggml-cuda/ec.cu`):
- The DFA decision today is in `post_compute` (~line 1296–1321): victim = resident with the lowest decayed score
  not requested this step; admit if `score[e] > best + kappa`.
- At `pre_compute`, per layer, compute on the host the set of experts that would pass that test *if missed this
  step*: `score[e] * decay^(step - last[e]) + 1 > best_victim_score + kappa`, where `best_victim_score` is the
  lowest decayed score among residents (the candidate order `cand` at ~line 676 already sorts residents by decayed
  score). Upload it as a per-layer bitmask (E bits) into pinned memory (reuse the `force` buffer mechanism added for
  `ORACLE_FETCH`: `ggml_ec_fetch::force`, `force_host`, `ec_fetch_plan_kernel` lines 131–160).
- In `ec_fetch_plan_kernel`, before the table path (line ~168): for each miss `cid[j]` whose bit is set, take the
  next victim from `vic` (lowest decayed score, not busy) and add the pair to the plan; then run the table path for
  the remaining misses with `T` reduced by the number already planned (or unchanged: decide and state it).
- `post_compute`: an expert fetched this way is resident (`slot_of` set by `publish_landed`); skip the background
  admission for it; count it under `fetches` and a new counter `fetch_admits`; write both to the stats JSON.
- Keep `kappa`, half-life and the table unchanged so the comparison is one factor.

**1b. Belady single-read prefetch** (`LLAMA_EC_ORACLE_LEAD_NOBYPASS=1`, with `ORACLE_LEAD=d`): the scheduled
single-read prefetch (`oracle_lead`, ~line 1256) with the MIN-bypass admission test removed: admit every
non-resident expert whose first use is ≥ `d` steps away, victim = furthest next use. This separates "admits what
the optimum bypasses" (over-admission) from "reads twice" on one host.

**1c. Order and cold start in `llama-ec-bench`** (`tools/ec-bench/ec-bench.cpp`): each `--ec` configuration already
gets a fresh `llama_context` (cold cache); add `--order shuffle --seed S` to run the configurations in a seeded
random order and record the order in the stats, and have the job run each cell twice with different seeds
(two launches per host are separate rentals; two orders within a launch are cheap).

**1d.** Regenerate the patch, commit on `gpu` with a test log, and extend `scripts/foresight_single_read_sim.py`
with the two new modes (`fetch-on-admit` is `scripts/foresight.py`'s `dfa-fetch` policy: the same decayed scores,
an admitted miss copied once and run on the GPU, the others on the CPU; the Belady-no-bypass lead is a one-line
change of the admission test).
